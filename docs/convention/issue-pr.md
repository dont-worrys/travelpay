# 이슈와 PR 양식

이 문서는 복사해서 사용할 텍스트 양식입니다. 실제 GitHub 이슈·PR 템플릿 자동 설정은 별도 작업입니다. 변경 내용에 해당하는 항목만 작성하고, 해당하지 않는 검증은 이유와 함께 `해당 없음`으로 표시합니다.

## BUG

이슈 제목 예시: `[BUG] 충전 요청 처리 상태가 갱신되지 않음`

```markdown
# 버그/에러 개요
<!-- 한 줄로 어떤 문제가 발생했는지 요약합니다. -->

## 발생 환경
<!-- 서비스·실행 환경·관련 버전 등 재현에 필요한 정보를 적습니다. -->

## 재현 방법
1. 첫 번째 동작
2. 두 번째 동작

## 예상 결과
<!-- 정상적으로 기대한 동작을 적습니다. -->

## 실제 결과
<!-- 실제 동작과 오류 메시지를 텍스트로 적습니다. 비밀번호·토큰·세션 값은 제외합니다. -->

## 해결할 작업
- [ ] 문제 원인 확인
- [ ] 수정 사항 구현
- [ ] 같은 문제가 재발하지 않는지 검증

## 참고 사항
<!-- 참고 사항과 영향받는 기능을 적습니다. -->
```

## FEAT

이슈 제목 예시: `[FEAT] 일반 회원가입 API 추가`

```markdown
# 기능 개요
<!-- 구현할 기능과 목적을 한 줄로 요약합니다. -->

## 구현 내용
- [ ] 구현 내용 1
- [ ] 구현 내용 2

## 완료 기준·검증 방법
<!-- 어떤 결과를 확인해야 완료인지 적습니다. -->

## 참고 사항
<!-- 다른 서비스와 합의할 계약이나 선행 작업을 적습니다. -->
```

## REFACTOR

이슈 제목 예시: `[REFACTOR] 지갑 상태 검증 책임 정리`

```markdown
# 리팩토링 개요
<!-- 대상과 개선할 이유를 적습니다. -->

## 유지할 동작과 변경 범위
<!-- 외부 계약과 유지해야 하는 동작을 적습니다. -->

## 개선할 작업
- [ ] 리팩토링 내용 1
- [ ] 관련 동작 회귀 검증

## 참고 사항
<!-- 영향 범위와 참고 사항을 적습니다. -->
```

## PR

PR 제목은 [커밋 규칙](commit.md)의 형식으로 작성합니다. 일반 개발 PR은 `dev`, 운영 반영 PR은 `main`을 대상으로 합니다.

```markdown
# 개요
<!-- 이번 PR의 문제와 결과를 한 줄로 요약합니다. -->

## 관련 이슈
<!-- 기본 브랜치로 머지할 때 자동 종료하려면 Closes #번호를 사용합니다. -->
<!-- 기본 브랜치가 아닌 PR이거나 참고 연결이면 Refs #번호를 사용합니다. -->
Closes #

## 작업 내용
- 작업 내용 1
- 작업 내용 2

## 검증
<!-- 실제 실행한 명령·조건과 결과를 적습니다. 수행하지 못한 검증과 이유도 구분합니다. -->
<!-- 테스트가 없는 초기 구성은 기동·HTTP·DB 확인 등 실제 수행한 검증을 기록합니다. -->
- 명령 또는 확인 방법:
- 결과:

## 체크리스트
- [ ] 변경한 동작과 관련 예외 상황을 검증했습니다.
- [ ] 공통 계약·환경 변수·DB 변경의 영향 범위를 확인했습니다.
- [ ] 변경에 필요한 가이드와 API 명세를 갱신했습니다.
- [ ] 관련 담당자에게 리뷰를 요청하고 리뷰어로 할당했습니다.

## 참고 사항
<!-- 필요한 환경 변수는 이름만 적고, 실제 비밀값은 포함하지 않습니다. -->
<!-- 특이사항·논의 사항·반영 순서를 적습니다. -->
```

`Closes #`에는 실제 이슈 번호를 채우고, 이슈가 없으면 해당 줄을 지웁니다. 자동 종료 조건은 [브랜치 규칙](branch.md)에 따릅니다.
